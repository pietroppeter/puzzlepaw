⏺ Good plan. Let me share some thoughts on the types before we write anything.

  Coord — a tuple is perfect in Nim:
  type Coord = tuple[row, col: int]

  HintLetter and HintWord — straightforward objects:
  type
    HintLetter = object
      pos: Coord
      letter: char
    HintWord = object
      pos: Coord
      word: string

  Problem — your design is clean. One small note: for the letter set, array[6, 
  char] works but you might also consider just using string or set[char] since
  the order doesn't really matter semantically. I'd lean toward array[6, char]
  since it enforces the fixed size and you'll want a known ordering for display
  (like the "A I L P S T" header in your puzzle image).

  Solution — here I'd suggest array[6, array[6, char]] (a 2D grid) instead of a
  flat array[36, char]. Accessing solution[row][col] is much more natural when
  checking sudoku constraints, and it pairs well with the Coord type:
  solution[coord.row][coord.col]. What do you think?

⏺ Here's how it works: since your .nimble file has srcDir = "src", nimble
  already knows where sources live. But the Nim compiler itself doesn't
  automatically pick that up when you run a test file directly.

  The standard approach is to add a small config file in the tests/ directory:

  Option A — tests/nim.cfg:
  --path:"../src"

  Option B — tests/config.nims:
  switch("path", "$projectDir/../src")

  Either one tells the compiler to look in src/ for imports. Then your test file
   can just do:

  import parloku/types
  import parloku/io

  No relative ../src/ prefix needed. Option A (nim.cfg) is simpler and more
  common. Want me to add it and update the test imports?

  Sources:
  - Nimble folder structure
  - Writing tests for Nim libraries
  - Nimble package structure wiki
