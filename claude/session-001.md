## What we built

Starting from an empty git repo, we set up the full project scaffolding and
built a working TUI puzzle player in a single session.

### Project setup

- Wrote `README.md` with project motivation, Parloku rules, and example
  puzzle images (problem + spoiler-protected solution).
- Created `.gitignore` for Claude Code (`.claude/`), Nim build artifacts,
  atlas dependencies, and compiled binaries.
- Initialized atlas (`atlas init`) for dependency management.
- Created `puzzleclaw.nimble` with illwill as a dependency.

### Parloku domain

Discussed and defined the Parloku puzzle format:

- 6x6 sudoku grid using letters instead of numbers.
- Word hints: Italian words that must be spelled starting from a marked cell,
  moving step by step to adjacent cells (horizontally or vertically).
- Letter hints: pre-filled cells as additional givens.

### Code

- `src/parloku/types.nim` — core types: `Coord`, `HintLetter`, `HintWord`,
  `Problem`, `Solution`.
- `src/parloku/io.nim` — pretty-print procs for Problem (with hint numbers
  in the grid) and Solution.
- `src/parloku/play.nim` — fullscreen TUI using illwill. Arrow keys to
  navigate, type letters to fill cells, colored word hint markers, completion
  detection.
- `tests/test_io.nim` — output capture tests for the pretty-print procs.

### Configuration files

- `nim.cfg` (root) — generated by atlas, sets `--noNimblePath` and dependency
  paths.
- `tests/nim.cfg` — adds `--path:"../src"` so tests can import with
  `import parloku/types` instead of relative paths.
- `config.nims` — defines a `nim play` task to launch the TUI.

## Decisions and discussions

- **Solution type as 2D array** — chose `array[6, array[6, char]]` over flat
  `array[36, char]` for natural `solution[row][col]` access.
- **0-based vs 1-based coordinates** — kept 0-based internally for now, noted
  it may feel unnatural. Not worth sweating yet.
- **atlas vs nimble for tasks** — `nimble play` triggers nimble's own
  dependency resolution which conflicts with atlas-managed deps. Solution:
  use `config.nims` tasks instead (`nim play`), which respects the
  atlas-generated `nim.cfg`.
- **Word hint visualization in TUI** — use a distinct color per word hint.
  The number shows in the grid cell before a letter is placed; word list
  below the grid uses matching colors.

## What I learned about Claude Code

- Claude Code creates a `.claude/` directory for local settings. It should
  be added to `.gitignore`.
- Claude can read images (PNG files) from the filesystem and understand
  their content — useful for extracting puzzle data from handwritten
  screenshots.
- Claude can fetch and read web pages to look up documentation (e.g., atlas
  docs, illwill API).
- Claude does not have a built-in session export/transcript command. Session
  logs must be written manually (by asking Claude to summarize at the end
  of each session).
- The conversation context does not persist between sessions. Each new
  session starts fresh.
