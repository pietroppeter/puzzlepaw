Solver

How many grids fit these clues? A tour of the constraint solver behind the future Parloku builder.

A Parloku is a 6×6 mini sudoku spelled with six letters, plus a few words threaded through the grid. The future builder page will let you pick letters, words and givens, and it needs to answer one question fast: how many solutions are left? This notebook explains the solver in src/parloku/solver.nim and runs it on the two puzzles in data/.

Every grey code block below runs while nimib builds the page, and its output is printed underneath. The last section is the same solver compiled to JavaScript, running in your browser.

01 · SUDOKUEach of the six letters appears once in every row, column and 2×3 box.
02 · WORDSEach word starts in its numbered cell and moves one step up, down, left or right per letter.
03 · FREEDOMBy the rules a path may step back onto a cell and two words may share cells. The solver can forbid both.

02 · THE BOARDThirty-six little sets

Internally the grid is 36 bitmasks, one per cell, where bit i means "letter i is still possible". Every cell has 20 peers (the cells that share its row, column or box). Two classic sudoku rules narrow the masks:

  • Naked single: when a cell is down to one letter, remove that letter from all its peers.
  • Hidden single: when a letter fits in only one cell of a row, column or box, it goes there.

Putting a letter in a cell is "eliminate the other five". Each elimination can set off more, and if any cell ends up with no letters left, the branch is dead. That is all the sudoku part needs. On its own it still leaves 28,200,960 possible 6×6 grids, so the words must do the real work.

03 · THE WORDSEvery word becomes a list of paths

A word with n letters starting at a cell can wander in at most 4n−1 ways. The solver lists them all up front and throws out the ones that cannot work in any grid:

  • a path that comes back to a cell must ask for the same letter there,
  • two different cells in the same row, column or box can never hold the same letter.

The second rule is what makes ITALIA interesting: its two A's and two I's must land in different rows, columns and boxes, so it has to cross box borders. Here is how many paths survive for each word, with and without revisiting:

var strict = defaultOptions()
strict.allowRevisit = false
for i, h in p1.wordHints:
  echo &"{h.word:<7} from {h.pos}: ",
    &"{wordPathCounts(p1)[i]:>3} paths (revisits allowed), ",
    &"{wordPathCounts(p1, strict)[i]:>3} without"
ITALIA  from (row: 5, col: 0):  25 paths (revisits allowed),  25 without
PASTA   from (row: 3, col: 0):  26 paths (revisits allowed),  26 without
ALPI    from (row: 1, col: 0):  15 paths (revisits allowed),  15 without

While the search runs, two things happen to these lists after every step:

  1. Pruning: a path dies as soon as one of its cells has lost the letter the path needs there. A word with no live paths kills the branch.
  2. Forcing: if every live path of a word goes through some cell, that cell can only hold one of the letters those paths ask for, so the solver narrows it. With a single live path, the whole word gets written in.

These two steps repeat, together with the sudoku rules, until nothing changes.

04 · COUNTINGBranch on cells, not on paths

When nothing more can be deduced, the solver picks the open cell with the fewest letters and tries each one. It branches on cells rather than on paths on purpose: one grid can spell a word along several paths, and branching on paths would count that grid more than once. Branching on cells counts each grid exactly once. solve stops at limit solutions and says whether it looked at everything:

let r1 = solve(p1)
echo "solutions: ", r1.count, "  (search complete: ", r1.complete, ", nodes: ", r1.nodes, ")"
echo "matches the answer key: ", r1.solutions[0] == puzzle1.solution
echo "isUnique: ", isUnique(p1)
solutions: 1  (search complete: true, nodes: 1)
matches the answer key: true
isUnique: true

One search node is enough: propagation alone solves puzzle 1. Now take the three givens away and see what the words manage by themselves:

var bare1 = p1
bare1.letterHints = @[]
let t0 = cpuTime()
let nBare = countSolutions(bare1, limit = 0)   # 0 = no cap, exact count
echo "puzzle 1 without givens: ", nBare, " solutions in ",
  formatFloat((cpuTime() - t0) * 1000, ffDecimal, 1), " ms"
puzzle 1 without givens: 42 solutions in 0.5 ms

05 · CANDIDATESThe true pencil marks

The count says how many. For building you also want to know where the freedom is. candidates returns, for each cell, the letters it takes in at least one solution. This is exact: each letter listed is backed by a real solution, unlike the pencil marks a human writes. A cell with one candidate is already forced by the words, so a given there would be wasted:

07 · STRICTER RULESElegant puzzles

The rules allow a path to revisit a cell and two words to share cells, but Pietro avoids both for elegance. SolveOptions can turn each one off, to check that a puzzle is also unique under the stricter reading, or to see how much of its freedom comes from overlaps:

let puzzle2 = loadPuzzle("../data/puzzle2-AMICA-GIOCO-MAGIA.json")
var bare2 = puzzle2.problem
bare2.letterHints = @[]
for (name, revisit, shared) in [("rules as written", true, true),
                                ("no revisits", false, true),
                                ("no shared cells", true, false),
                                ("neither", false, false)]:
  var o = defaultOptions(limit = 0)
  o.allowRevisit = revisit
  o.allowShared = shared
  echo &"{name:<17} puzzle1: {solve(bare1, o).count:>3}   puzzle2: {solve(bare2, o).count:>3}   (no givens)"
var strictest = defaultOptions()
strictest.allowRevisit = false
strictest.allowShared = false
echo "with givens, unique under the strictest reading: ",
  solve(p1, strictest).count == 1, " and ", solve(puzzle2.problem, strictest).count == 1

09 · CAN WE TRUST IT?Cross-checked by brute force

The no-givens counts (42 and 34, and 24 for puzzle 2 without revisits) were checked against a plain brute force run that walks all 28,200,960 grids and tests each word with checkGrid. That takes about five and a half minutes. The solver gives the same numbers in milliseconds. The test suite (tests/test_solver.nim) keeps these numbers fixed, and checks both answer keys.

This is the same solver.nim, compiled with nim js. Pick a puzzle or paste a code. Each cell shows its candidate letters. Tap a small letter to make it a given, and tap a given to remove it. The count and the code update as you go, and you are done when the count reaches 1.

candidates at (5,4) without the P given: @['P']

This count says how many solutions there are, not how hard they are to find. Pietro solves a Parloku by hand by writing each word's first letter, then following the words letter by letter wherever the sudoku rules leave only one place, and finishing with plain sudoku. A step-by-step solver that copies that method could rate difficulty in the builder. It is a natural next tool.
